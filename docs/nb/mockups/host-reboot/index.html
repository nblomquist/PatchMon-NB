02 / Safety & availability

Manual means available—not accidental.

A pending-update flag is not required.
Connection, permissions, and operation guards still apply.

Confirmation / Any time

No restart required? Still your call.

Manual reboots are allowed. The confirmation identifies the host, explains downtime, and makes clear that this reboot is operator-requested rather than update-required.

Unavailable / Offline

Always visible, not queued for later.

The header button stays in place but is disabled when the agent cannot receive the request. The banner retains the security warning and explains the connection issue.

Available / No pending restart

Quiet page. Reboot still available.

No banner when an update does not require a restart. Reboot remains enabled, in the same place and normal toolbar styling—not a larger call to action.

03 / Smaller screens

Same button.
Same place.

Fetch, Patch, and Reboot share one row of equally sized header actions. Secondary tools sit below. The security notice remains a separate message, not a large reboot control.

  • Reboot button matches the existing 38px height.
  • Banner only when an installed update needs a restart.
  • Manual reboots still require confirmation.

Next / Your call

How does this
balance feel?

Button & noticeThe compact header action is always present. Does the security banner stand out enough without making the whole page feel urgent? Is “Reboot” clear enough as the short toolbar label?

Security & confidenceThe security reason here is synthetic. Implementation must use confirmed update metadata before labelling a pending restart security-related. Unknown reasons should get a generic reboot-required notice.
